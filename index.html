    Array search vs Map lookup

    Finds 2,000 IDs in a 50,000-item collection using Array.find (scans) and Map.get (hash lookup).

    How the code is organised

    fp module
    Reusable functional helpers: pipe, compose, curry, and memoize (a closure holding a private cache Map).
    Data module
    Sample data generation, validation, the store, Map indexes, Sets, immutable updates, deduplication, queries, pure calculations, the iterable, and the batch generator. It never touches the DOM.
    Demo module
    Execution-order demo and the Array vs Map benchmark.
    UI module
    Reads state, calls Data, and renders HTML. It owns all event handlers.
    Data structures
    Map groups records by status, user, and category and indexes them by ID, so filters start from the smallest group instead of scanning all records. Set holds unique categories, users, and statuses and drives deduplication. A WeakMap stores view counts keyed by record object; when a record object is dropped, its entry can be garbage collected. A Symbol (SRC) marks each record's origin without clashing with normal property names.
    Functional techniques
    Pure functions: total, sumValue, avgValue, completionPct. Currying: where(key)(value)(record). Composition: queries use pipe. Memoization: summarize caches by data version plus filter, and is cleared whenever data changes. Immutability: records are frozen, and updates and dedupe return new objects and arrays.
    Iterator
    RecordCollection implements [Symbol.iterator]() and returns an object with next(), so it works in for...of and spread. The generator batches wraps any iterable and yields 10 records per step; yield* delegates to it.
    Performance comparison
    Array search is O(n) per lookup; Map is O(1) on average. Limits: one machine, one run, JIT warm-up and garbage collection add noise, performance.now() is deliberately coarse in browsers, and the Map costs extra memory and build time (shown separately).
    Safety
    Invalid records (null, missing fields, bad status, impossible dates, negative values) are rejected on load and counted. Empty results show a message, search input is trimmed and escaped, and pages are clamped.
